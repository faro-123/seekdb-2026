# 迁移消融诊断版：本地验收

2026-11-15。基于 781a14dfe07ce0e7f7a387b9717f0f87ff651430，分支 codex/minivectordb-migration-ablation-20261115。用户要求尝试去掉部分 seekdb 迁移方法，并尝试去掉 AMD hipVS 方法。此版本是分组诊断实验，尚未平台提测，不是已确认的准入修复或性能采用版。

## 实际范围

默认 Cargo feature `migration-ablation` 关闭三条路径：

1. Stage 内存暂存：现有文件后端处理全部非空暂存，保留读取器偏移和失败语句隔离。
2. 紧凑提交块编码：新提交使用 MVTX0001，关闭跨行字典/前后缀/RLE 与页对齐块写入；读取旧紧凑 WAL 的能力保留。
3. HotCache：默认预算固定为零，通用精确查询负责结果，禁用热快照、紧凑整数/half 热扫描和等值位置复用。

保留单向量无损编码、密集位置索引、LIMIT 驻留修复、解析器、提交前同步及恢复语义。没有新增依赖，Dockerfile、Cargo.lock、公开驱动和题包不变。`--no-default-features` 恢复原优化路径；标准 Docker 构建启用消融。

AMD 历史复用只在本地旧测试适配包，没有 HIP/ROCm/CAGRA 数据库运行时可移除。本轮独立写了整数公式向量及 Python 欧氏距离真值，不导入旧适配包；历史文件保留。此实验也关闭了成功版已经拥有的热查询，因此不是精确回退 c919 之后全部变化。

## 性能代价

同机 2 CPU/2 GiB，1 万行、128 维、100 个写事务、20 条预热和 200 条计时 exact 查询。小整数公式输入，单轮墙钟请求耗时；不是原六项工作负载，不替代原性能报告。

| 版本 | 写请求总计 ms | 200 查询 ms | WAL 逻辑字节 |
| --- | ---: | ---: | ---: |
| c919 成功参照 | 364.315 | 151.015 | 1,323,662 |
| 781 原优化版 | 268.464 | 93.774 | 1,024,235 |
| 当前消融版 | 265.173 | 926.718 | 1,323,662 |

该输入查询耗时约为 781 的 9.88 倍、c919 的 6.14 倍。WAL 文件尺寸不等于设备 I/O；单轮写入数值不能声称有稳定收益。本版本不宜作为冲击性能 5000 的候选，仅供用户选择是否消耗一次机会验证这组路径的准入影响。

## 结论边界

独立代码审阅未发现阻塞或重大正确性缺陷；该结论和本地测试不能替代未知隐藏用例。781 已被用户确认平台失败，提示“mysql正式用例未完成”，原因未定位。分组消融即使平台通过也不能区分是暂存、提交块还是热查询；若仍失败也不能排除保留路径。原 2026-competition-round2 分支此次不自动替换，平台由用户手动提测。
